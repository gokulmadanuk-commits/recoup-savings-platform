# Tech Stack Notes

PARSING / INGESTION: pdfjs-dist (getTextContent for per-glyph x/y + font size; the only lib that exposes positions needed to rebuild table rows/columns) for server-side, with unpdf as the serverless/Vercel build (self-contained pdf.js v5, worker embedded; reach the same items via getResolvedPDFJS()). pdf-parse only for quick flat-text needs; AVOID pdf2json (memory leaks, uncatchable errors that defeat 'never let one bad doc kill the batch'). exceljs for Excel reads (typed cells via Enums.ValueType, streaming WorkbookReader, ~6x less memory than SheetJS - decisive under serverless limits), with SheetJS (xlsx) as fallback for .xls/.ods/CSV. mammoth for .docx -> HTML (emits thead, preserves merged cells), then node-html-parser to walk tables. ROBUSTNESS: p-limit (cap concurrency 4-8), Promise.allSettled (one rejection must not abort the batch), worker_threads pool to isolate the rare uncatchable pdf.js crash; religiously call loadingTask.destroy() per PDF and page.cleanup() per page (the #1 cause of heap growth). VALIDATION / NORMALIZATION: zod for the schema-first canonical model with per-field coercion and a 0-1 confidence score (source quality + safeParse success + cross-checks like line-sum==total + parser warnings); route sub-threshold docs to human review. MONEY / DETERMINISM: decimal.js or integer-cents bigint everywhere - never JS floats - so cumulative overcharges don't drift; string-similarity / fast-levenshtein for the >=0.85 fuzzy line-matcher and duplicate-detection thresholds; all thresholds as named, version-pinned config. EXTERNAL DATA: native fetch / node-fetch for the BLS CPI-U API (cache the trailing-12-month figure, store the value used with each finding). TEST-FIXTURE GENERATION: PDFKit >= 0.15.0 (fixed ToUnicode map, tagged Table/TR/TH/TD structure, embedded subsettable fonts) so generated invoices/contracts round-trip through the extractor; pdf-lib only when modifying/stamping existing PDFs; round-trip self-test (generate -> extract -> assert cells equal source) as the built-in verification harness. NEVER rasterize tables to images. FRONTEND: editorial finance-grade surface - Tailwind with the forest/paper/gold token set; Fraunces + Newsreader + Inter via Google Fonts (tabular-nums + lining-nums on all figures); SVG feTurbulence grain at 3-5% opacity; charts via a lib themed to the brand palette (forest/emerald/gold/verdant, never default blue), thin 1.5-2px strokes, flat. If built as an Astro lead-gen surface keep client JS at zero (pure-CSS entrances via @starting-style / scroll-driven animations); respect prefers-reduced-motion. SCHEDULING: Vercel Cron for the daily sliding-window rules (R01 auto-renewal, R08 prospective early-pay); rule batches run on new-invoice ingest (R02/R06/R07) and monthly + on-demand at renewal-prep (R03/R04/R05/R09/R10). TESTING: a unit suite per detection rule against the synthetic corpus answer key (the corpus IS the source of truth - each planted finding must fire its rule at the expected dollar figure), plus the PDF round-trip harness.
